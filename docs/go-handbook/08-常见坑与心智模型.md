# 08 · 常见坑与心智模型

> 这些不是语法问题，是心智模型问题。每个新手都会踩。
> 来源：原 `GO_GUIDE.md` §11 五个坑 + 各处 C/C++ 对照。

---

## 🔴 坑 1：interface nil ≠ 底层值 nil

```go
var p *Task = nil           // p 是 nil 指针
var e Embedder = p          // e 不是 nil！
fmt.Println(e == nil)       // false！！！  (Go 新手最震撼的时刻)

// 原因: interface 内部是 (type指针, value指针) 对
// e 的内部: (type=*Task, value=nil) — type 不是 nil, 所以 interface 不是 nil

// 正确做法: 返回具体 nil，不要返回有类型的 nil
func getEmbedder() Embedder {
    return nil  // ✅ 直接返回 nil
}
func getEmbedder() Embedder {
    var p *HTTPClient = nil
    return p    // ❌ BUG: 返回的 interface 不是 nil
}
```

**后果**：`if summarizer != nil { summarizer.Summarize(...) }` 可能对"nil 指针装的 interface"误判为非 nil，然后调用时 panic。**规则：返回 interface 的函数，失败时显式 `return nil`，不要 `return 具体nil指针`。**

## 🔴 坑 2：slice 底层共享

```go
a := []int{1, 2, 3}
b := a[0:2]          // b 和 a 共享底层数组！
b[0] = 99            // a 也变了！ → a = [99, 2, 3]

// append 可能脱离共享，也可能不脱离
b = append(b, 4)     // 容量够 — 覆盖 a[2]，a = [99, 2, 4]
b = append(b, 5, 6)  // 容量不够 — b 搬新家，脱离共享

// Python 切片是拷贝，Go 切片是视图 — 这是 C 的心智模型
```

**对 C/C++ 读者**：Go 的 slice ≈ C++ 的 `std::span` / 指针+长度。切片操作零拷贝，**改 b 会改 a**。要独立副本用 `copy(dst, src)` 或 `append([]T(nil), src...)`。

## 🔴 坑 3：值接收者 vs 指针接收者

```go
// 值接收者 — 操作的是副本
func (t Task) SetTitleBad(s string) { t.Title = s }     // 无效！外面不变

// 指针接收者 — 操作的是原件
func (t *Task) SetTitleGood(s string) { t.Title = s }   // 正确

// interface 满足规则不同:
type Updater interface { Update() }
func (t Task) Update()  {}   // Task 满足 Updater, *Task 也满足
func (t *Task) Update() {}   // 只有 *Task 满足 Updater, Task 不满足！

// 规则: 指针类型的方法集包含值接收者的方法，反过来不行
```

**对 C++ 读者**：等价于"成员函数参数按值还是按引用"。**大 struct 一律用指针接收者**——避免复制开销。**如果你用值接收者实现接口，而某处要传指针，编译会报错**——这是最常见的"为什么 *Task 不满足接口"困扰。

## 🔴 坑 4：defer 的参数求值时机

```go
x := 1
defer fmt.Println(x)  // 参数 x 在 defer 这一行就求值 → 最终打印 1
x = 2                 // 改变不了上面

// 对比: 闭包捕获的是变量本身
x = 1
defer func() { fmt.Println(x) }()  // 最终打印 2 (执行时才取值)
x = 2
```

**规则**：`defer f(args)` 的 `args` 在 defer 语句执行时求值；`defer func(){...}()` 的闭包在函数返回时执行、取当时的变量值。想要"执行时快照"用闭包，想要"注册时快照"直接传参。

## 🔴 坑 5：for-range 的变量复用

```go
// Go 1.21 及以前 — 经典 bug:
for _, t := range tasks {
    go func() { process(t) }()
    // BUG: 所有 goroutine 都用了最后一次循环的 t
    // 因为 t 变量在整个循环中复用同一个地址
}

// 修复 (Go 1.21):
for _, t := range tasks {
    t := t                      // 用 := 创建循环体内新变量
    go func() { process(t) }()  // OK
}

// Go 1.22+ 已自动修复 (PlanAI 用 go 1.25，但这个坑值得知道)
```

**对 C++ 读者**：这就是"range-based for 里捕获循环变量引用"的经典 bug 的 Go 版本。Go 1.22 起循环变量每轮独立，但**老的代码/老 Go 版本仍会踩**。看到 `for _, x := range` 里 `go func(){...x...}()` 就要警惕。

## 为什么会有这些坑：底层原理

这些"坑"不是语言 bug，而是**实现原理的自然结果**。理解了原理，坑就消失了。

### interface 为什么有 nil 陷阱？— 它是两个字长的结构体

```go
// interface 值在内存里是两个字（两个指针）：
type iface struct {
    tab  *itab              // 类型信息表（type + 方法表）
    data unsafe.Pointer     // 实际值的指针
}
```

`var e Embedder = (*Task)(nil)` 时：`e.tab` 指向 `*Task` 的类型表（**非 nil**），`e.data` 是 nil。所以 `e == nil` 为 false——**nil 判断比较的是整个 iface，不是 data**。

这解释了为什么"返回具体 nil 指针"会踩坑，也解释了为什么标准库函数敢返回接口然后让你 `if r == nil` 判断——只要它**显式返回 nil 字面量**，iface 两个字都是零，`r == nil` 就成立。

### slice 为什么是视图？— 为了零拷贝

```go
// slice 头也是三个字：指向底层数组的指针 + len + cap
type slice struct {
    data unsafe.Pointer
    len  int
    cap  int
}
```

切片 `a[0:2]` **只复制这三个字的头**，底层数组共用——所以零拷贝。代价就是你改 `b[0]` 会改到 `a`。C++ 的 `std::span` 完全一样；Python 切片是深拷贝，所以没这个问题（但慢）。

**避坑心法**：
- 只想读：随便切片。
- 要独立副本：`copy(dst, src)` 或 `append([]T(nil), src...)`。
- 想安全 append 到共享 slice：先保证 `cap` 够（`make([]T, 0, 足够)`），否则 append 可能就地覆盖他人数据。

### defer 为什么参数先求值？— 语法决定

`defer f(x)` 是**注册一个调用**，参数在注册时压栈；`defer func(){...}()` 注册的是**闭包**，函数体执行时才取变量。这就是语言语义，不是坑——记住"传值 vs 传闭包"两个方向即可。

### for-range 变量复用为什么修了？— 语义不清的代价

Go 1.22 之前，循环变量是"一个变量，每轮赋值"（复用地址），导致闭包捕获错乱。Go 1.22 改为**每轮新建变量**——这是 Go 极少数为修坑而改语义的地方，说明这坑够深。**兼容保证**让 Go 只能靠版本行为切换，老代码在 1.22 编译后行为不同，但绝大多数正确。

## 避坑清单（按项目实战）

| 坑 | 项目里怎么避免 | 对应位置 |
|---|---|---|
| interface nil | 返回接口时显式 `return nil`，不返回 nil 指针 | `ai/noop.go`、`app/app.go` |
| slice 共享 | 需要副本时用 `append([]T(nil), src...)` | `mcp/mcp.go` 常见 |
| 值/指针接收者 | 大 struct + 需要修改 → 一律指针接收者 | `proxy/proxy.go` 的 `responseWrapper` |
| defer 求值 | 想"执行时快照"用闭包 | `u/log.go` 的 `defer logMu.Unlock()` |
| for-range 闭包 | 用 go 1.25（已自动修复）；老代码要 `t := t` | 无 |
| 并发读 map | 用 `sync.Map` 或 `map+RWMutex` | `proxy/context_inject.go` |

## 附：Go 心智模型的一句话总结

| 你以前会的 | Go 对应 | 关键差异 |
|---|---|---|
| C++ 类 + 继承 | struct + 方法 + embedding | 组合不是继承，接口隐式满足 |
| C++ 异常 / Python raise | 多返回值 + error | 错误是正常数据流，不是控制流 |
| C++ RAII | defer | 函数级，LIFO，panic 也执行 |
| C++ 模板 | 泛型 `[T any]` | 克制，仅接口约束，项目里只用了 2 处 |
| pthread | goroutine | 2KB 栈、自动调度、成千上万 |
| `std::map` 并发 | `sync.Map` / `map+RWMutex` | 并发安全但值要类型断言 |
| Python dict / list | `map[string]any` / `[]string` | 类型固定，JSON 解析要手动断言 |
| Python 切片（拷贝） | slice（视图） | 切片操作零拷贝，改共享数组 |
