## 2. HTTP — 三层路由器

AIPMC 有**三个** HTTP 层，职责不同：

```
web/server.go  ── 前端大门 ──► /pmai/* → api 处理器
                              /__proxy/* → proxy 处理器
                              / 其他 → 静态文件 + SPA 兜底
                                 │
api/server.go  ── API 路由 ──►  chain of handleXxxRoutes 每个返回 bool
                                 │
proxy/proxy.go ── 代理路由 ──►  http.NewServeMux + handler() 按路径 switch
                                 (/v1/messages, /v1/responses, /v1/chat/completions, /v1/models)
```

### 层 1 — Web 前端大门 (`web/server.go:41 Listen()`)

```go
func (s *Server) Listen() error {
    apiMux := http.NewServeMux()
    apiMux.HandleFunc("/pmai/", func(w http.ResponseWriter, r *http.Request) {
        s.apiHandler.ServeHTTP(w, r)
    })
    apiMux.HandleFunc("/health", ...)

    fileServer := http.FileServer(http.FS(s.staticFS))

    wrapper := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        // 1) /pmai/* 和 /health → API 处理器
        // 2) /__proxy/* → proxy 处理器
        // 3) 其他 GET → 静态文件，404 时 SPA 兜底回 index.html
    })
    http.ListenAndServe(addr, wrapper)   // 阻塞监听
}
```

**SPA 兜底**：前端路由（如 `/tasks/123`）在服务器没有对应文件时，返回 `index.html` 让 React 自己渲染——这是单页应用的标配，Go 里几行 `fs.ReadFile` 就搞定。

### 层 2 — API 手工路由器 (`api/server.go:32 ServeHTTP`)

项目不用任何路由框架。`Server.ServeHTTP` 是一串返回 `bool` 的 handler 方法链：

```go
func (s *Server) ServeHTTP(w http.ResponseWriter, r *http.Request) {
    if s.handleChatRoutes(w, r) { return }
    if s.handleWebRoutes(w, r) { return }
    if s.handleQueryRoutes(w, r) { return }
    if s.handleMutateRoutes(w, r) { return }
    // ...
}
```

每个 `handleXxxRoutes` 内部 `switch path` 命中就处理并返回 `true`，否则返回 `false` 交给下一个。**没有路由表、没有中间件库**——这是项目自己的路由约定。

### 层 3 — 代理中心 handler (`proxy/proxy.go:342 handler()`)

```go
func handler(w http.ResponseWriter, r *http.Request) {
    path := r.URL.Path
    agent := detectAgent(path)

    rw := &responseWrapper{ResponseWriter: w, status: 200}

    // 读请求体
    body, _ := io.ReadAll(r.Body)
    r.Body = io.NopCloser(bytes.NewReader(body))  // ← 恢复 r.Body（读完就没）

    // 路由分发
    switch {
    case path == "/v1/messages":
        handleClaudeUnified(rw, r)
    case path == "/v1/responses":
        handleCodexUnified(rw, r)
    }

    recordTraffic(agent, r.Method, path, rw.status, rw.size)
}
```

### 关键技术点：`io.NopCloser` 恢复 `r.Body`

`http.Request.Body` 是 `io.ReadCloser`，**只能读一次**。`io.ReadAll` 读完后必须用 `io.NopCloser(bytes.NewReader(body))` 重建，否则后续 handler 读不到数据。

### 关键技术点：`responseWrapper` 捕获状态码

```go
type responseWrapper struct {
    http.ResponseWriter    // 嵌入接口 — 提升所有方法
    status int
    size   int
}
func (rw *responseWrapper) WriteHeader(code int) {
    rw.status = code
    rw.ResponseWriter.WriteHeader(code)
}
```

因为 `http.ResponseWriter` 的 status code 只能写一次且写入后不可读。Wrapper 拦截 `WriteHeader` 记录状态码供统计使用。这是 Go 中扩展接口行为的标准做法——wrapper 实现相同接口，拦截感兴趣的方法，其余透传给原始实现。（详见过往 [02 · 类型系统](02-类型系统与接口.md) 的 struct embedding。）

## 3. JSON — marshal / unmarshal / 类型断言

### `json.Marshal` — Go struct → JSON

```go
type ReviewResult struct {
    SessionID string `json:"session_id"`
    Intent    string `json:"intent"`
    Score     int    `json:"-"`
}

r := ReviewResult{SessionID: "abc123", Intent: "coding", Score: 70}
b, _ := json.Marshal(r)
// → {"session_id":"abc123","intent":"coding"}
//   Score 被忽略 — json:"-" 表示跳过
```

### `json.Unmarshal` — JSON → Go struct

```go
var l2 SessionL2Summary
if err := json.Unmarshal([]byte(ss.Summary), &l2); err != nil {
    continue  // JSON 格式异常，跳过
}
```

**`&l2`** 传指针——Unmarshal 需要修改结构体的内容，所以必须传地址。

### 处理动态 JSON — `map[string]any`

项目中对未知结构的 JSON 常用 `map[string]any`：

```go
var raw map[string]any
json.Unmarshal(body, &raw)
messages, ok := raw["messages"].([]any)  // 类型断言
if !ok {
    return body  // 格式不对，原样返回
}
```

**`raw["messages"].([]any)`** 是类型断言——把 `any` 类型断言为 `[]any`。如果类型不匹配，`ok` 为 false。这是 Go 处理动态 JSON 的关键技巧。

## 4. database/sql + SQLite — db ↔ store 分工

```
db/    只管"连上"：sql.Open("sqlite", 路径+WAL pragma)、建表/迁移、配置与凭据
store/ 只管"查询"：ListTasksFor / CreateTask / UpdateCommit ... 每个都是纯函数
                 （内部 pmdb.Open() → SQL → Scan 行 → 返回 []map[string]any）
```

### 打开连接（`db/db.go:113`）

```go
d, err := sql.Open("sqlite", dbPath+"?_pragma=journal_mode(WAL)&_pragma=busy_timeout(15000)&_pragma=synchronous(NORMAL)")
```

- `modernc.org/sqlite` 是**纯 Go** 驱动，不需要 CGO——这是项目能在无 C 编译器的机器上构建的原因。
- WAL 模式 + `busy_timeout(15000)` 是处理 SQLite 并发读写的关键 pragma。

### 行扫描（`store/` 模式）

```go
row := db.QueryRow("SELECT title FROM tasks WHERE id = ?", id)
var title string
row.Scan(&title)      // 手动把列拷进变量 — 比 Python 啰嗦但类型安全
```

**对 C**：`?` 占位符 ≈ C 的绑定参数（比 sprintf 拼 SQL 安全得多）。**对 Python**：相当于 `sqlite3`，但每一列都显式 `Scan` 到类型化变量，SQL 注入天然不可能。

### 事务 + 并发退避

多进程并发写 SQLite 会 `SQLITE_BUSY`。项目在 `store/store.go:1713` 用 `BEGIN IMMEDIATE` 事务 + `retryOnBusy` 指数退避（详见 [04 · 错误处理](04-错误处理与资源管理.md) §7）。

## 5. context — 项目里的两个真实使用

`context.Context` 在项目里用得很少（没穿透函数签名），只有两处：

```go
// vision/vision.go:386 — 给视觉请求 180s 超时
ctx, cancel := context.WithTimeout(context.Background(), 180*time.Second)
defer cancel()

// store/store.go:1730 — 事务用 context.Background()
conn, err := db.Conn(context.Background())
conn.ExecContext(context.Background(), "BEGIN IMMEDIATE")
```

> 这是项目的**非惯用设计选择**：代码显式传 `*sql.DB` 和 `time.Time`，而不是把 context 穿到每个函数签名。读到 `context.Background()` / `WithTimeout` 知道是干嘛的即可——大多数函数不需要 context。

## 6. go:embed — 把前端嵌进二进制

```go
//go:embed frontend/dist    // 把整个 React 构建产物嵌入二进制
var uiFS embed.FS

// 使用：serveCommand() 里 fs.Sub(uiFS, "frontend/dist") 得到子目录
//      再传给 web.NewServer(staticFS, ...) 由 http.FileServer 托管
```

**限制**：
1. 只能嵌入当前目录或子目录的文件 — 不能用 `../` 不能用绝对路径
2. 嵌入的是编译时的文件内容，运行时修改文件不影响嵌入内容

**Python 对比**: 需要打包工具 (PyInstaller) 或者运行时读取文件系统。
**C 对比**: 需要手动用 xxd 转成字节数组再链接。

## 7. 为什么这么设计：标准库的哲学

### 7.1 为什么 Go 内置 HTTP 服务器？

Go 的定位是"云基础设施语言"，HTTP 服务是它的主战场。所以 `net/http` 从 1.0 起就提供**生产级**的服务器——自带连接池、keep-alive、TLS、HTTP/2、反向代理能力。你不需要 Flask/Django/Express，`http.ListenAndServe` 就是全部。

**对比**：Python 的 `http.server` 只适合开发调试，生产要 gunicorn/uwsgi；Node 要 Express。Go 的 `net/http` 直接能上生产——项目 `web/server.go` 就用它跑了整个 Web 服务。

### 7.2 Handler 接口为什么是核心抽象？

```go
type Handler interface {
    ServeHTTP(w http.ResponseWriter, r *http.Request)
}
```

**整个 net/http 都建立在这一个接口上**：

- `http.HandlerFunc` 把普通函数转成 Handler（函数也是值，见下）
- `http.NewServeMux` 是一个 Handler（分发器）
- 中间件就是"包一层的 Handler"
- `http.FileServer` 返回的也是一个 Handler

```go
// 函数转 Handler — 项目 web/server.go:61
wrapper := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
    // ...路由分发...
})
http.ListenAndServe(addr, wrapper)
```

**思维方式**：`Handler` 接口 = 一切 HTTP 处理的统一入口。你想扩展（记录日志、加 CORS、鉴权），就写一个 Handler 包另一个 Handler：

```go
// 中间件模式：接收 Handler，返回 Handler
func logging(h http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()
        h.ServeHTTP(w, r)
        u.LogShared("HTTP", "%s %s %s", r.Method, r.URL.Path, time.Since(start))
    })
}
```

### 7.3 database/sql 为什么用 driver 模式？

`database/sql` 提供**统一接口**，具体数据库靠**驱动**注册：

```go
import _ "modernc.org/sqlite"   // 空导入：只执行驱动的 init() 注册自身

// 之后一律用统一的接口
db, _ := sql.Open("sqlite", "path")
db.QueryRow("SELECT ...")
```

- **空导入 `_ "modernc.org/sqlite"`**：Go 特有。导入只是为了触发 `init()`，不直接用它名字。换数据库（MySQL/Postgres）时，只换这行 import 和 DSN 字符串，**业务代码一行不用改**——这就是接口抽象的威力。
- **driver 模式**：Go 1.0 时就定了。任何数据库只要实现 `database/sql/driver` 接口就能接入。

**对 Python 读者**：类似 PEP 249（DB-API），但 Go 的 driver 接口更严格、类型更安全（`Scan(&x)` 需要指针）。

### 7.4 "let the standard library do the work"

Go 社区习惯：**优先标准库，别急着引第三方框架**。项目正是如此——HTTP、JSON、SQL、加密、时间、排序全部用标准库，第三方依赖只有 4 个（uuid、x/term、x/text、sqlite）。依赖少 = 编译快、体积小、安全面小。

**思维方式**：遇到需求先问"标准库有吗？"——`sort.Slice`、`strings.Builder`、`sync.Map`、`time.Ticker` 这些常用武器要熟。
