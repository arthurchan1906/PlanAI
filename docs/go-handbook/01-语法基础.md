## 1. 编译 vs 解释

```
Python:  source.py ──(解释器)──► 运行
JS:      source.js ──(V8/JIT)──► 运行
Go:      source.go ──(编译)──► 二进制文件 ──► 运行
C:       source.c  ──(编译)──► 二进制文件 ──► 运行
```

Go 和 C 一样是编译语言。但 Go 编译极快（几千行代码 < 1 秒），而且**交叉编译**一行命令：`GOOS=linux go build` 就能在 Windows 上编译出 Linux 二进制。

**PlanAI 为什么用 Go**：编译后是一个单文件（`aipmc` / `aipmc.exe`），不需要 Python 环境、不需要 `pip install`、不需要 Node.js。用户复制文件就能跑。

## 2. 没有运行时依赖

```go
//go:embed frontend/dist
var uiFS embed.FS        // React 前端打包进 Go 二进制

// Python: 你需要 manage.py collectstatic + nginx 配置
// JS:     你需要 serve 静态目录
```

Go 的 `embed` 指令在**编译时**把文件嵌进二进制。PlanAI 的整个 Web UI（React + Ant Design）就靠这一行打包进 `aipmc`。

## 3. 文件结构

```go
package main          // 必须声明包名。main = 可执行程序入口

import (              // Python: import; JS: require/import
    "fmt"             // 标准库: 格式化输出, 类似 Python print
    "strings"         // 字符串操作
    "aipmc/ai"        // 项目内模块, 路径是 go.mod 的 module 名 + 子目录
)

func main() {         // 程序入口 = C 的 main(), Python 的 if __name__ == "__main__"
    fmt.Println("hello")
}
```

### 对应关系

| Go | Python | JS |
|---|---|---|
| `package main` | 文件名就是模块 | `export` |
| `import "fmt"` | `import os` | `require("fs")` |
| `func main()` | `if __name__ == "__main__"` | 自动执行 |
| `//` 单行注释 | `#` | `//` |

## 4. 变量声明

```go
// 短声明（最常用）——等价于 Python 的 x = 1
x := 1                     // Go 自动推断类型 int
name := "hello"

// 显式声明
var count int              // C 风格: int count; 零值初始化 (0, "", nil)
var msg string = "world"

// 常量
const MaxSize = 100        // JS 的 const
```

### 零值

| 类型 | 零值 | Python 类比 |
|---|---|---|
| `int` | `0` | `int()` → 0 |
| `string` | `""` | `str()` → "" |
| `bool` | `false` | `bool()` → False |
| `*T` (指针) | `nil` | `None` |

> **对 C/C++**：`var count int` 就是 `int count;`，但 Go **自动初始化为零值**——不会有 C 里"未初始化读脏内存"的未定义行为。

## 5. 函数

```go
// Python: def add(a, b): return a + b
func add(a, b int) int {
    return a + b
}

// 多返回值（Python: return a, b）
func divide(a, b int) (int, error) {
    if b == 0 {
        return 0, fmt.Errorf("division by zero")  // 抛出错误
    }
    return a / b, nil  // nil = Python 的 None, 表示无错误
}

// 方法: 给 struct 绑定函数（类似 Python class 的 method）
func (s *Server) Start() error {  // (s *Server) = Python 的 self
    // s 是 Server 实例的指针
}
```

### 同类型参数简写（项目里到处都是）

```go
// 连续多个同类型参数可以合并写类型
func logDiscussion(sessionID, role, source, content, metadataJSON string) (map[string]any, error)
//                                                               ^^^^^^ 只写一次 string

// Python 等价:
// def log_discussion(session_id: str, role: str, source: str, content: str, metadata_json: str)
```

## 6. 控制流

```go
// if——和 C 一样。Go 没 while, 用 for 代替
if x > 0 {
    // ...
} else if x < 0 {
    // ...
}

// for——唯一的循环语句
for i := 0; i < 10; i++ { }     // C 风格
for _, item := range items { }   // Python: for item in items
for condition { }                // Python: while condition
for { }                          // 无限循环

// switch——不需要 break（Go 默认 break）
switch status {
case "done":
    // ...
default:
    // ...
}
```

### Python / JS 对照

| Go | Python | JS |
|---|---|---|
| `for _, x := range arr` | `for x in arr` | `for (x of arr)` |
| `for i := 0; i < n; i++` | `for i in range(n)` | `for (let i=0; i<n; i++)` |
| `switch x { case "a": }` | `match x: case "a":` (3.10+) | `switch(x) { case "a": }` |
| `if err != nil` | `if error:` | `if (error)` |

## 7. 字符串和字节 — string vs []byte

```go
s := "hello"           // string — 只读，UTF-8 编码
b := []byte(s)          // []byte — 可读写，用于 I/O、JSON 解析
s2 := string(b)         // []byte → string
```

### 项目中的转换链路

```go
// proxy/context_inject.go
body []byte                      // HTTP 请求体原始字节
↓
var raw map[string]any           // 需要先转为 map 才能操作
json.Unmarshal(body, &raw)       // []byte → map
↓
raw["instructions"] = ...        // 修改
↓
b, _ := json.Marshal(raw)        // map → []byte
return b                          // 返回修改后的字节
```

**为什么 `json.Unmarshal` 接受 `[]byte` 而非 `string`**：JSON 数据本质是字节流。接受 `[]byte` 避免了 `string(data)` 的额外内存分配。这是 Go 的零拷贝哲学——能用 []byte 的地方不用 string。

## 8. PlanAI 项目核心模式（热身）

#### 模式 1: 数据库操作

```go
func createTask(title string) (map[string]any, error) {
    db, err := openDB()           // 1. 打开连接
    if err != nil { return nil, err }
    defer db.Close()              // 2. 确保关闭

    id := slug("task")            // 3. 生成唯一 ID
    now := nowISO()               // 4. 当前时间戳

    _, err = db.Exec(             // 5. 执行 SQL
        "INSERT INTO tasks (id, title, created_at) VALUES (?, ?, ?)",
        id, title, now,
    )
    if err != nil { return nil, err }

    return getTask(id), nil       // 6. 读取并返回
}
```

#### 模式 2: 工具函数

```go
slug("task")    → "task-20260607-123456-a1b2c3"
nowISO()        → "2026-06-07T12:34:56"
str(nil)        → ""
jsonStr(v)      → JSON 序列化
```

> 这些辅助函数对应真实项目 `u/u.go` 里的 `Slug` / `NowISO` / `Str` / `JsonStr`。

## 9. 为什么这么设计：Go 的起源与心智

### 9.1 Go 是怎么来的

2007 年 Google 内部，**Rob Pike、Ken Thompson、Robert Griesemer** 在等一个大型 C++ 程序编译时产生了共识：C++ 编译太慢、太复杂；Java 太重、太啰嗦。他们想要一门语言：

- **编译快**（几千行 < 1 秒，当 `python script.py` 用）
- **语法极简**（25 个关键字，一门语言一天上手）
- **内建并发**（多核时代，Google 靠 C++ 手搓线程池太痛苦）
- **自动垃圾回收**（但比 Java 更轻）

> 注意设计者之一 **Ken Thompson 就是 Unix 和 C 的共同发明人**。所以 Go 骨子里是 C 的简化派——去掉了指针算术、宏、头文件，保留了"编译产物即部署产物"的 Unix 哲学。

2009 年开源，2012 年 Go 1.0 发布并承诺向后兼容（至今成立）。

### 9.2 时间格式为什么是 2006-01-02 而不是 %Y-%m-%d？

这是 Go 新手第一个"什么鬼"。原因：

```go
// Go 用"参考时间"，不用 C/Python 的格式符
now := time.Now()
now.Format("2006-01-02 15:04:05")   // Go 写法
// Python 等价: now.strftime("%Y-%m-%d %H:%M:%S")
```

**"2006-01-02 15:04:05" 是一个记忆魔咒**：1月2日 下午3点04分05秒 2006年——按美国日期习惯 `01/02 03:04:05 '06` 排列，恰好是 **月/日/时/分/秒/年**：

| 数字 | 含义 |
|---|---|
| `01` | 月（1 月） |
| `02` | 日（2 日） |
| `03`（或 `15`） | 时（3 点 / 24 小时制 15 点） |
| `04` | 分 |
| `05` | 秒 |
| `2006` | 年 |

好处：一眼看出每个字段代表什么，不用查表。代价：第一次看到的人一脸懵。

**项目里到处都是**（`u/u.go`）：

```go
func NowISO() string { return time.Now().Format("2006-01-02T15:04:05") }
func Today() string  { return time.Now().Format("2006-01-02") }
func Slug(prefix string) string {
    b := make([]byte, 3)
    rand.Read(b)
    return fmt.Sprintf("%s-%s-%s", prefix, time.Now().Format("20060102-150405"), hex.EncodeToString(b))
}
// Slug("task") → "task-20260824-220545-a1b2c3"
```

`Slug` 生成的 ID：前缀 + 紧凑时间戳 + 3 字节随机 hex。全项目的 task/commit/plan ID 都靠它保证唯一。

### 9.3 零值哲学 — "make the zero value useful"

Go 没有构造函数语法。变量声明出来就是**零值**：

```go
var count int          // 0
var name string        // ""
var p *Task            // nil
var task Task          // 所有字段都是零值
```

设计者刻意让零值**可用**（Go 谚语 *"Make the zero value useful"*）：

- `var buf bytes.Buffer` 零值即可直接写
- `var m map[string]int` 零值（nil map）可以**读**（返回零值），只有**写**才 panic
- `var mu sync.Mutex` 零值即可加锁——不需要 `new(Mutex)` 或构造器
- `var w http.ResponseWriter` 接口零值是 nil，配 `if w == nil` 做降级

**项目例子**——`proxy/context_inject.go` 的缓存直接声明零值 struct 就用：

```go
var sessionCache struct {
    mu        sync.RWMutex   // 零值可用，直接能 Lock()
    goals     []string
    updatedAt time.Time
}
```

**对比 C**：C 的未初始化局部变量是**脏内存**（随机值），读它是未定义行为。Go 强制零值，从语言层面杜绝了"忘记初始化"这类 bug。

> **思维方式**：看到 `var x T` 不用急着找构造函数。零值就是默认状态；如果你的类型零值没意义，通常说明设计有问题（应该让零值可用）。
